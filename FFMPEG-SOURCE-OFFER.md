`configure` script needed to reproduce the build.

- File: `FFmpeg-Builds-bd26828f0e96.tar.gz`
- Size: 116,585 bytes
- SHA-256: `dbc3300d6ecd096c3f903d17aeb01bd0ee6dbd77abb14592afd2e98367a37167`

Reproducing the binary means: build the `win64-lgpl` image from Archive 2 with
the FFmpeg source from Archive 1 checked out at the pinned commit. The build
stamps the date, so a rebuild made on a different day will differ from the
shipped binary in its `--extra-version` and its bytes; the code it compiles is
identical.

## 3. How to exercise your right to the source

- Download both archives from the release page for this version.
- Verify them against the SHA-256 values in §2.
- Extract Archive 1 to read the source and the licence texts; extract
  Archive 2 to reproduce the build.

If either asset is missing from the release page — because the release was
taken down, or because three years have passed — write to the repository's
issue tracker and the maintainer will provide the corresponding source. This
offer is made by the distributor of Reels Downloader, not by the FFmpeg
developers or by `BtbN`, and it is valid for at least three years from the
release of this version.

## 4. How to replace `ffmpeg.exe`

The application is installed **per user**, not per machine, so the folder it
installs into is writable by the account that installed it — no administrator
rights are needed to swap the binary.

1. Close Reels Downloader.
2. Open the install folder. It is the folder the application's About page
   reports as its installation location, and it is where `ffmpeg.exe` sits
   beside `yt-dlp.exe` and the licence files.
3. Replace `ffmpeg.exe` with your own build, or with any
   other FFmpeg build you trust. Rename it to exactly that name.
4. Start the application again.

The application discovers the tools by looking in that folder and passes them
`--ffmpeg-location <that folder>`, so a replacement build is picked up
automatically. Reels Downloader only invokes them as separate processes with
command-line arguments (see §5); it does not require a particular FFmpeg
version, a particular linking style, or a particular build variant. A
dynamically linked build works as well as a static one.

## 5. What this means for the application itself

Reels Downloader does not compile, link, or embed any FFmpeg code. It runs
`ffmpeg.exe` as a child process and reads its output. The
application is therefore not a work derived from FFmpeg by linking; the LGPL
v3 obligations that apply here are the obligations of *conveying* the binary
itself — the licence text (`FFMPEG-LICENSE-LGPLv3.txt`), this
written offer, and the Installation Information in §4.

**A note on section 4 of the LGPL v3, stated plainly.** The shipped build is
statically linked, and this offer provides the complete source and the
complete build system rather than the object files that section 4's
static-linking clause contemplates. Because §4 lets the user replace the
library with a different build entirely — which this application supports,
since it does not link FFmpeg at all — the practical ability the clause exists
to protect is available. **This is the project's reading, not a legal
determination.** The choice of how to discharge section 4 for a static build
was made by the application's owner, and the owner's own legal sign-off is
recorded as required before redistribution. See
`reports/PHASE_R1_LICENSING.md`.
